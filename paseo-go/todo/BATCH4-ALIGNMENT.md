## F8 会话所有权状态机（用户 2026-09-30，裁定 13）

**反馈链**：「手机发起→回电脑 omp 续跑，provider 要跟着变；原生会话被外部续写要感知并标非原生；非原生定时同步更新；对非原生进行中发消息警告；对非原生已完成发消息转原生。」+「先做 lite，full 单独调研文档。」

**模型（与出生标签正交）**：现有 `paseo.imported-provider-session` 标签=出生史**不动**；新增**所有权轴** `ownership: paseo | external | none`（协议纯增，进 agent 目录；官方 app 忽略未知字段已证）。

- `paseo`：daemon 的 provider 进程活着。
- `none`：进程死且 transcript 无外部变动——谁先发谁得。
- `external`：进程死但 transcript 有外部变动（watcher 实锤）。

**拍板**：

1. **R1**（原生自动更新/推送）：现状已成立，零改动。
2. **R3**（非原生同步）：server 对 transcript 路径 `fs.watch`+防抖 → tail 重读 → timeline 增量 + `lastMessagePreview` 更新 + 未读/红点走现有链；网络盘/事件丢失兜底=低频 stat(mtime+size) 轮询。
3. **R2-lite**（降级感知）：并入 R3 watcher——`none/paseo(已死)` 态下检测到外部写 → `external`，行上标「外部」小徽标（标题行，灰）。
4. **R4**（非原生进行中发消息警告）：`external` 且 looksActive（mtime 启发式）→ 发送前警告弹窗：「该会话可能正在外部终端运行，继续发送将从此会话 resume 新进程，可能产生分叉或冲突」+「取消 / 仍要发送」；仍要发送=走 R5 路径（lite 期自担风险，full 调研后可能收紧为禁止）。
5. **R5**（非原生已完成发消息→转原生）：现有 `resumeAgentFromPersistence` 路径 + 所有权翻转为 `paseo` 记账；完成后再退出→回 `none`/`external` 按 R2-lite 判。
6. **UI 联动**：F4 行=「外部」徽标位（与「导入」出生徽标区分：所有权轴优先显示）；F7 已导入行同样可得 external 态（导入屏徽标=出生轴，两处语义在卡内写清不混用）。
7. **R2-full 剥离**：双写者数据安全 → 独立调研文档 `paseo-go/RESEARCH-provider-dual-write.md`（已立），调研结论出来前 R2-full 不实现。

### 裁定 14（用户 2026-09-30 追加）：UI 展示强制

**反馈原话**：「我刚才说的这些逻辑，ui 上都要有展示。具体 ui 执行 agent 可以先自行设计，但是不能只停留在后端数据。」

- F8 全部状态/事件必须有**可见 UI**：`external` 徽标（列表行+会话屏顶栏）、R3 同步到达的新消息走未读红点/预览刷新、R4 警告弹窗、R5 发送成功后的状态翻转可见（徽标消失/转圈出现）。
- **具体视觉由执行 agent 自主设计**（徽标形态/色/文案/位置可自定，与现有 token/i18n 体系一致即可）；
- **验收硬线**：真机帧必须证明「一眼分辨某会话是 paseo/external/none」+「外部续写后列表无需手动刷新即可见变化」；**只有协议字段和 server 逻辑、无 UI 呈现 = 验收不过**。

**影响面**：协议纯增 `ownership`（messages.ts 触点+重生成 validators）/ server agent-manager+providers 各 transcript 路径知识（watcher 生命周期挂 agent 记录）/ 壳行徽标+警告弹窗+i18n / 官方 app 零影响（忽略字段）。可行性序：R5<R4<R3<R2-lite（R2-full 除外）。

## F9 返回键=先退搜索（用户 2026-09-30，裁定 15）

**反馈原话**：「一个通用问题：搜索的时候，返回键应该退出搜索回到非搜索状态，而不是切页面。」
