## F17 诊断（代码实证，已闭合）

**答用户：后端已更新**（生产=0.10.2-go.7，今晨升级自检全绿）。导入屏=真 bug，**服务端过滤与 F7 徽标设计互相矛盾**：

1. **徽标必然不显示**：`import-sessions.ts` 把所有「已存在为 agent」的会话（**含已归档**，R2-19 注释明确归档不豁免）从列表**整个剔除** → 该打徽标的行不下发 → 壳侧徽标匹配无数据可标。F7 口径=显示+徽标+勾选禁用+点行直达；server 行为=直接消失。
2. **只有子没父**：父被上述规则剔除 → 子以 orphan-group「子会话 · X · N」落顶层（设计内组头，触发条件=父被剔）。
3. **比 omp resume 少** = 已存在剔除 + metadata-generation 剔除 + limit 60 三重过滤；omp resume 无过滤。截图仅 ~7 行 ≪ 60，说明剔除吃掉大头。
4. 截图「如果额外问题…」行=本会话（原生启动仍在列表）→ 原生 agent 的 persistence handle 为何不匹配 transcript handle，卡内查（这决定徽标键的可靠性）。

**修复方向（待拍板 Q1）**：server 停止剔除，响应纯增 `existing:{agentId,archived}` 服务端判定字段；壳恢复徽标行+勾选禁用+点行直达。协议纯增向后兼容。
