# C11 通知：等待批准可达性

## 背景 / 用户拍板

DESIGN.md §8。手机场景核心价值=agent 等批准时能叫人。基线 = C10 HEAD。

## 设计裁定（照此执行，不得重开）

- spike 官方 expo-notifications 基建（FCM/推送通道是否已接 daemon 事件）；结论写 `paseo-go/NOTIFY.md`
- 目标行为：任一 host 的 agent 进入等待批准/出错 → 通知（标题=会话名，正文=需要的动作），点击→直达该会话
- 官方推送通道不可用（需官方 FCM 凭据等）→ 降级：前台本地通知 + 已连接时后台 headless 轮询（尽力而为），并在 known_issues 写明"锁屏后台推送依赖官方通道"
- 壳设置加通知开关（默认开）；系统权限请求时机=首次触发等待批准事件时

## 范围

- 动：`src/shell/notify.ts`、接线、壳设置项、locales、`paseo-go/NOTIFY.md`
- 不动：官方源文件（若必须改官方才能通推送 → 停，记 known_issue 上报编排者）

## 验收（四项证据契约）

1. typecheck+lint 零错误
2. app 包测试全绿（事件→通知内容映射单测）
3. 真实运行：真机制造"等待批准"（agent 请求权限不批）→ 收到通知 → 点击直达会话 → 批准；退后台再试一次记录实际可达性
4. 读图：≥2 张（通知栏展开、点击直达后的会话）

- 恰好一次 commit
