# KI-11 对话列表长按/拖动/置顶一致性（用户拍板 2026-09-29）

## 用户裁定（原话拆解，四条全做）

1. **长按生效那一刻立刻弹菜单**——不是松手才弹。
2. 菜单已弹出后若手指**上下拖动** → 立即隐藏菜单、**转入拖动排序逻辑**。
3. 现拖动 bug：**向下拖触发下拉刷新**，只有向上拖能进拖动——两向都要能进拖动，
   拖动期间刷新闸必须关。
4. **拖动产生的置顶/取消置顶与菜单置顶按钮疑似逻辑冲突**——一起查清并统一。

## 现状代码图（编排者已定位，卡内为准）

- 长按菜单：C3 官方菜单引擎 ContextMenu 形态（`chat-row-menu.tsx`），
  触发时序=官方语义（疑为松手弹，实测口径以你复现为准）。
- 长按拖动接力：C20 `use-shell-row-drag-menu.ts`（+test）——长按后转拖动的既有机制在这。
- 置顶/排序：`pins` store（`paseoGo.` 六 store 之一）；菜单 pin 行与拖动落点各自写哪条路径=待查。
- 刷新：chats 列表 `RefreshControl`（`chats-screen-body.tsx`），拖动与它的竞争=第 3 条根因候选。

## 实现口径

1. **时序**：长按阈值到点即开菜单（手指未松也可开；官方引擎若不满足→用
   gesture-handler LongPress 程序化打开，姿势照 C20 接力层做，不改上游文件）。
2. **菜单→拖动接力**：菜单可见期间纵向位移超阈 → 关菜单 + 同手势无缝进入行拖动
   （C20 已有接力骨架，扩"菜单已开"入口；不许出现"菜单关了但拖动没接上"的断档）。
3. **双向拖动**：拖动激活即 `refreshing=false` + 禁用 RefreshControl（拖动结束恢复）；
   向下/向上拖都进排序；列表顶部向下拖=拖动而非刷新（拖动模式里刷新只由"未长按的普通下拉"触发）。
4. **置顶一致性（先查后修，报告必含发现）**：
   - 钉死两条路径现行为：菜单 pin 切换 vs 拖入/拖出置顶区的写入（store 字段/副作用/排序键）；
   - 统一模型：**拖动跨区=pin/unpin，且必须调用与按钮同一个 store action**（单一真相，
     副作用零分叉）；区内拖动=纯排序；
   - 若发现两者语义本应不同（如拖出≠取消置顶）→ hub 报 Main 附证据，不自行拍板。

## 验收（证据契约四项）

1. app typecheck + oxlint 零错误。
2. 定向：`use-shell-row-drag-menu` 扩展用例（菜单开→位移→接力；双向阈值；刷新闸开关）+
   pins store 跨区=同 action 用例；app 套件失败集=W1 基线零新增。
3. 真机（MatePad，置顶若干会话）：①长按不松手→菜单已现（**手指未抬的帧**为证）；
   ②菜单开着往下拖→菜单消失+行跟手（中间态帧）；③顶部向下拖=排序不是刷新（无 spinner 帧）；
   ④拖出置顶区 vs 按钮取消置顶→落盘状态逐字段一致（dump 对照）。
4. 读图 ≥4 存 `paseo-go/evidence/KI11/`。
