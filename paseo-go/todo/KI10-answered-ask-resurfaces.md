# KI-10 已回答的交互提问在时间线回放中复活为待答态（用户报告 2026-09-29）

## 现象（用户截图）

Paseo 会话屏监看编排者会话：数天前 C18 时代已回答的 ask widget
「R2-02/03（P1×2）：未读双拍重构选哪种？(1/4)」重新以**可交互待答态**弹出
（含 关闭/提交 按钮）。该题当时已拍板 a) 上提总线+离开即结算并落地发货
（`src/shell/chats/visit-ledger.ts`，C18 卡验收通过）。

## 定性

**状态 bug**：已回答的交互式工具调用（ask/问题 widget）在时间线重建/重连回放时
未落成"已答"只读态，被重新渲染为可提交。风险=用户误提交过期答案 → 脏数据注入会话。

## 归属与待钉死

- 会话数据流：harness(omp) 提问 → daemon 时间线 → 官方会话屏渲染。三处都可能：
  ① harness 侧 ask 结果未随历史下发 answered 标记；② daemon 投影丢状态；
  ③ app 渲染层对历史 ask 一律按 pending 渲染。
- 复现路径待钉死：是否只在**重连/切后台回前台/翻历史**时出现；关闭后是否复发；
  其它会话的已答 ask 是否同样复活。
- 壳侧 vs 官方侧：渲染体在官方会话屏（上游文件）→ 若钉死为 ②/③，进
  `UPSTREAM-ISSUES.md`；若 ①（harness 桥），属 omp 侧记录，不在本仓修。

## 影响面

监看场景的误导/误操作风险；无数据损坏路径（除非用户提交）。

## 临时口径

告知用户：历史提问 widget 复活时点「关闭」勿「提交」。
